Worksheet 2 — the scatter plot, and what it hides

Tableau Desktop · 25 min

  1. New worksheet. credits_attempted to Columns, credits_earned to Rows.

One mark — the grand total. Tableau aggregated everything into a single point.

  1. Drag student_id to Detail. One mark per student.
  2. Drag status to Color.
  3. Analytics pane → drag Trend Line → Linear onto the view. Hover it for R².

The chart says 1,400 students. Count the dots you can actually see.

What's actually happening

Credits come in multiples of three, so 1,400 students land on only 38 distinct positions. The busiest point — 18 attempted, 18 earned — has 195 students stacked on a single dot. A scatter plot with overplotting this heavy shows you where values exist, not where students are.

Fix it

Use at least one of these, and keep the fix in the submitted sheet:

  • Color → drop opacity to about 30% and add a mark border, so stacked points darken.
  • Or take student_id off Detail and put CNTD(student_id) on Size, with status still on Color. Each dot's area now carries how many students sit there.
One more comparison

Swap the axes for undergrad_gpa and total_aid_awarded and read R² again. You don't need to keep that version — but your caption will use the number. Then say plainly what an R² does not establish.

Worksheet 3 — the ethics of the axis

Tableau Desktop · 25 min

You'll build the same chart twice — once honestly, once deceptively — then find out that even the honest one was hiding something.

  1. New worksheet. campus_name to Columns.
  2. is_withdrawn to Rows → Measure → Average. The average of a 0/1 flag is a rate.
  3. In the Data pane, right-click is_withdrawn → Default Properties → Number Format → Percentage, 1 decimal. Add labels.

Identical numbers. On the truncated copy, Online's bar looks about ten times Main's. The real gap is 20.1% against 12.8%.

The point

Bar length is the encoding in a bar chart. Cut the baseline and the length the reader measures stops matching the value. A line tracking change over time is a different case — truncation there is often defensible, and knowing why is the actual skill.

Connect mvu_student_dim.csv, then drag mvu_enrollment_fact.csv onto the canvas beside it. Tableau draws a flexible line — a relationship. Set it to student_id = student_id.

  1. New worksheet. From the student table, put three measures on Text: student_id as Count (not Count Distinct), is_graduated as Average, and total_aid_awarded as Sum.
  2. Name the sheet Worksheet 1 — Relationship.
  3. Duplicate the data source (right-click it → Duplicate). In the copy, double-click a table to open the physical layer and rebuild the link as an inner join on student_id.
  4. Duplicate the worksheet, then Data → Replace Data Source to point it at the joined copy. Name it Worksheet 1 — Join.
RelationshipInner join
Count of student_id1,40010,147
Graduation rate53.8%70.6%

What just happened

A relationship keeps each table at its own grain. A join flattens both into one wide table at the enrollment grain, so every student is repeated once per course. The count and the total inflate — and so does the rate, which is harder to spot: graduates took more courses, so they're repeated more often, and the join weights the average toward them.

Module 2 · Step 4 of 8

Worksheet 2 — clean, then deduplicate

Tableau Desktop or Prep · 35 min

Your Worksheet 2 caption needs three documented quality problems, each with a before-and-after count. This data has more than three; these are the ones worth writing up.

1 — Inconsistent categories

sex holds eight spellings of two values. residency holds eleven spellings of three. Keep the original field and build a cleaned one beside it:

UPPER(TRIM([sex]))

That takes sex from 8 values to 4 (F, FEMALE, M, MALE) and residency from 11 to 9 — spacing and case, but not wording. Finish with an alias or a group.

2 — Whitespace and case in a join key

program_code has leading or trailing spaces on 109 rows and lower-case codes on 63. Invisible on screen, fatal to a join — "CSCI " does not match "CSCI".

UPPER(TRIM([program_code]))

3 — Numbers stored as text, and impossible values

undergrad_gpa contains blanks and N/A, which forces the field to string. Change the type to Number (decimal) and the non-numeric entries become null. Then handle the values above 4.0:

IF [undergrad_gpa] > 4.0 THEN NULL ELSE [undergrad_gpa] END

Then deduplicate — in the right order

The 2021 file repeats some students — some rows exactly, some differing only in the capitalisation of the name. Standardise first, UPPER(TRIM([student_name])), then remove duplicates or aggregate to one row per student_id.

Order of operations

Deduplicate before standardising and the capitalisation variants survive, because "ALI, DIEGO A." and "Ali, Diego A." are different strings. Clean first, then dedupe. This bug is quiet, common, and produces a number that looks almost right.

Checkpoint

How many rows does deduplication remove, done in the right order?

Show the expected answer

13

1,413 down to 1,400. If you removed only 9, the capitalisation duplicates are still in there — standardise the name field first. For the GPA fix: 27 values sit above 4.0.

Worksheet 3 — check for join fan-out

Tableau Desktop · 20 min

financial_aid.xlsx holds one sheet per aid year. Union the four sheets first — 3,897 rows — then look at the grain: several rows per student, one per aid year per aid type.

  1. Left join the aid union to your cleaned, deduplicated student table on student_id.
  2. On a scratch sheet, put student_id on Text twice: once as Count, once as Count (Distinct).

The two numbers split apart. Every student is now repeated once per award, so any count of students — and any average of a student-level field — is wrong.

The fix is grain, not deletion

  1. Aggregate the aid data to one row per student first (sum the award amounts), then join.
  2. Or use a relationship and let Tableau aggregate at the right level for each view.
Explicitly required

Do not delete records to make totals match. Removing rows until a number looks right destroys the analysis and is the specific failure this part of the exercise tests for.

One more thing to catch: 68 students — about one in twenty — have no aid record at all. An inner join would drop them, for the same reason it dropped the unmatched programs.

Worksheet 1 — row-level versus aggregate

Tableau Desktop · 25 min

↓Exercise 3 handoutPDF · 62 KB · the graded version of this module: what to build, the caption questions and what to submit.

This distinction causes more wrong numbers than any other calculation topic. Build both and compare.

Connect mvu_student_dim.csv. Create a calculated field named Aid per Credit (row):

[total_aid_awarded] / [credits_attempted]

This computes per student, then Tableau aggregates the results. Now the aggregate version, Aid per Credit (agg):

SUM([total_aid_awarded]) / SUM([credits_attempted])

Put college on Rows and both fields on Columns. Set the first to Average. Format both as currency with no decimals. Name the sheet Worksheet 1.

CollegeAvg of ratios (row)Ratio of sums (agg)
Liberal Arts$2,014$1,235
Science & Engineering$1,853$1,215
Business$1,659$1,161
All students$1,783$1,200
Why they differ

The first is an average of ratios — every student counts the same regardless of how many credits they took. The second is a ratio of sums, so students with heavier loads pull it further. Students with few credits and a full aid package produce huge per-credit ratios that the first version counts in full. Neither is wrong. Which one you want depends on whether your question is about the typical student or the typical dollar.

The error you'll hit

"Cannot mix aggregate and non-aggregate arguments" means you wrote something like SUM([a]) / [b]. Everything inside one calculation must sit at the same level.

Checkpoint

Aid per Credit (agg) across all students, to the nearest dollar? (Remove college from the view, or add a grand total.)

Show the expected answer

1200

$36,527,620 ÷ 30,441 credits. The row-level average across all students is $1,783. If your grand total for the row version doesn't match $1,783, check its total is set to Average rather than Sum.

Pull a string apart

The term code packs two facts into one string. Pull them apart.

LEFT([term_code], 4)

That's the calendar year. And the season:

IF RIGHT([term_code], 2) = "FA"

Part A — Answer these without opening Tableau

Say each answer out loud or write it down before you open the box. Recognising an answer is not the same as being able to produce one.

1. What is the difference between a relationship and a join, and when does it matter?

A relationship keeps each table at its own grain and aggregates each one appropriately for whatever is in the view. A join flattens tables into one wide table, repeating rows from the smaller side. It matters any time you count or average something from the smaller table — student counts, averages of student-level fields, or any total that should not be multiplied by the number of related records.

Revisit: Relationships versus joins

2. Why does cleaning have to happen before deduplicating?

Duplicate detection compares strings exactly. Two records that differ only in capitalisation or trailing whitespace are different strings, so they survive a duplicate removal. Standardise the field first, then deduplicate.

Revisit: Clean, then deduplicate

3. When do an average of ratios and a ratio of sums give different answers?

Whenever the denominator varies across records. The average of ratios weights every record equally; the ratio of sums weights records by size. The gap widens as your records become more unequal. Neither is wrong — they answer different questions.

Revisit: Row-level versus aggregate

4. What does a level-of-detail expression do that a normal calculation cannot?

It computes at a grain you specify rather than the grain of the view, and holds that grain even when the view's dimensions change. Use it when you need a per-entity value — a first date, a maximum, an entity total — inside a view that is broken out by something else.

Revisit: One value per student

5. Why did the 2022 cohort show a zero percent graduation rate?

The data ends in Spring 2023. That cohort had two terms to complete a multi-year programme, so nobody could have graduated. The chart is reporting the boundary of data collection, not student performance.

TermMeaning
AddressingThe dimension the calculation moves along. Here, term.

Observable · 35 min

In Tableau, dropping a measure on Rows created the axis, chose the range and started it at zero. Here each of those is a line you write.

{
  const width = 800, height = 420;
  const margin = {top: 30, right: 20, bottom: 90, left: 60};

  // Scales: data values in, pixel positions out
  const x = d3.scaleBand()
    .domain(rates.map(d => d.college))
    .range([margin.left, width - margin.right])
    .padding(0.2);

  const y = d3.scaleLinear()
    .domain([0, 1])                                  // a rate: zero to 100%
    .range([height - margin.bottom, margin.top]);    // SVG y grows downward

  const svg = d3.create("svg")
    .attr("width", width).attr("height", height)
    .attr("viewBox", [0, 0, width, height]);

  // One rect per row of data
  svg.append("g").selectAll("rect")
    .data(rates)
    .join("rect")
      .attr("x", d => x(d.college))
      .attr("y", d => y(d.rate))
      .attr("width", x.bandwidth())
      .attr("height", d => y(0) - y(d.rate))
      .attr("fill", "steelblue");

  // Axes
  svg.append("g")
    .attr("transform", `translate(0,${height - margin.bottom})`)
    .call(d3.axisBottom(x))
    .selectAll("text").attr("transform", "rotate(-25)").style("text-anchor", "end");
  svg.append("g")
    .attr("transform", `translate(${margin.left},0)`)
    .call(d3.axisLeft(y).tickFormat(d3.format(".0%")));

  // Labels: the rate, and how many students it rests on
  svg.append("g").selectAll("text")
    .data(rates)
    .join("text")
      .attr("x", d => x(d.college) + x.bandwidth() / 2)
      .attr("y", d => y(d.rate) - 6)
      .attr("text-anchor", "middle").attr("font-size", 12)
      .text(d => `${d3.format(".1%")(d.rate)} (n=${d.n})`);

  display(svg.node());
}

A dashboard needs the same chart more than once, so turn your Module 9 chart into a function. Two helper cells:

function rateBy(rows, key, field) {
  return Array.from(
    d3.rollup(rows, v => ({value: d3.mean(v, d => d[field]), n: v.length}), d => d[key]),
    ([k, o]) => ({key: k, value: o.value, n: o.n})
  ).sort((a, b) => d3.descending(a.value, b.value));
}
function barChart(rows, {width = 640, height = 360, color = "var(--brand)"} = {}) {
  const margin = {top: 28, right: 16, bottom: 80, left: 48};
  const x = d3.scaleBand().domain(rows.map(d => d.key))
    .range([margin.left, width - margin.right]).padding(0.2);
  const y = d3.scaleLinear().domain([0, 1])
    .range([height - margin.bottom, margin.top]);
  const svg = d3.create("svg").attr("viewBox", [0, 0, width, height]);  // no fixed width: it scales
  svg.append("g").selectAll("rect").data(rows).join("rect")
    .attr("x", d => x(d.key)).attr("y", d => y(d.value))
    .attr("width", x.bandwidth()).attr("height", d => y(0) - y(d.value))
    .style("fill", color);   // style, not attr, so CSS variables work
  svg.append("g").attr("transform", `translate(0,${height - margin.bottom})`)
    .call(d3.axisBottom(x))
    .selectAll("text").attr("transform", "rotate(-25)").style("text-anchor", "end");
  svg.append("g").attr("transform", `translate(${margin.left},0)`)
    .call(d3.axisLeft(y).ticks(5).tickFormat(d3.format(".0%")));
  svg.append("g").selectAll("text").data(rows).join("text")
    .attr("x", d => x(d.key) + x.bandwidth() / 2).attr("y", d => y(d.value) - 6)
    .attr("text-anchor", "middle").attr("font-size", 12)
    .text(d => `${d3.format(".1%")(d.value)} (n=${d.n})`);
  return svg.node();
}

Module 10 · Step 5 of 6

Section 3 — make it work on a phone

Observable · 20 min

A 12-column grid on a phone gives each chart a sliver. A media query changes the rules below a width you choose. Add this to your style cell:

@media (max-width: 700px) {
  .main-chart, .side-chart { grid-column: span 12; }   /* stack the charts */
}

The KPI cards already wrap on their own — that's what flex-wrap and the 180px minimum do. The charts scale because the SVG has a viewBox and no fixed width.

Test it: narrow your browser window, or open the notebook on your phone.

Scaling isn't the same as working

On a phone the main chart shrinks to fit — and so do its labels, which become too small to read. Stacking fixed the layout, not the chart. Options: rotate to a horizontal bar chart on narrow screens, drop the n labels into a tooltip, or pass a smaller width to barChart so the text renders larger relative to the space. Pick one and say why in your caption.

Tableau's equivalent

Device layouts (Dashboard → Device Preview) do the same job: a different arrangement below a certain width. Module 5 skipped them; this is what they're for.
